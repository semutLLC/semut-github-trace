# Semut GitHub Trace

Capture software development as a trace stream.

## Overview

Every software project generates a history of actions:

* Commits
* Issues
* Pull Requests
* Releases
* Branches
* Discussions
* Contributors

Most repositories focus on the final code.

Semut GitHub Trace focuses on the history that produced the code.

This repository collects and analyzes GitHub activity as a sequence of traces that can later be transformed into:

Trace → Memory → Knowledge → Norm → Institution

For the full vision see:
[docs/VISION.md](docs/VISION.md)

## Goals

### Trace Layer

Capture repository events:

* Commits
* Issues
* Pull Requests
* Releases
* Tags
* Discussions

### Memory Layer

Organize traces into persistent histories:

* Repository timelines
* Contributor histories
* Development patterns
* Project evolution

### Knowledge Layer

Extract patterns from development history:

* Common workflows
* Collaboration structures
* Project lifecycles
* Successful development practices

### Norm Layer

Identify recurring behaviors that emerge across projects:

* Repository structures
* Release strategies
* Documentation standards
* Collaboration practices

### Institution Layer

Preserve successful norms through templates, automation, and shared tooling.

## Why

Software repositories contain more than code.

They contain evidence of how coordination emerges.

By studying development traces over time, we can better understand how teams, projects, and communities evolve.

## Status

Early prototype.

## Relationship to Semut

Semut proposes a layered model:

Trace → Memory → Knowledge → Norm → Institution → Ideology

This repository explores that model within software development ecosystems.

Every commit becomes a trace.

Every repository becomes a memory.

Every pattern becomes knowledge.

Every repeated pattern can become a norm.
